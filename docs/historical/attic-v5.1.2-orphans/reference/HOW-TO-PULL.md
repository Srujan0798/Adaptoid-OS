# How To Pull From the Reference Library

> OS-Setup is not just a structure generator — it's a **DevKit with a library**. This `reference/ecosystem/` is the library: a curated catalog of the agentic-AI ecosystem (tools, SDKs, skills, patterns, people, optimizations) from the last 6 months of trending repos and leading practitioners.
>
> The orchestrator consults it **like a reference shelf** — pulling only the entries relevant to the detected archetype + tier. It does NOT load the whole library into context (that would be FM-04 bloat). It reads `ecosystem/INDEX.md`, then the 2–4 catalog files that matter, then picks specific tools.

## The pull loop (run during project setup, after archetype + tier are chosen)

```
1. Read ecosystem/INDEX.md            → the card catalog (small)
2. Read ecosystem/SELECTION.md        → archetype → recommended stack mapping
3. Pull the 2–4 catalog files that match this project's needs, e.g.:
     - always: protocols-standards.md (MCP/A2A/skills are universal)
     - if coding-heavy: coding-agents.md, optimizations.md
     - if agent-product: sdks-adks.md, orchestration-multiagent.md
     - if memory matters: memory-context.md
     - if knowledge/RAG: knowledge-systems.md
4. From those, choose specific tools. Record the choice + WHY in docs/decisions/ (ADR).
5. Wire the chosen tools into the generated project (mcp.json, requirements, skills/).
6. Do NOT keep the catalog files in active context after choosing. Compact to the ADR.
```

## The principle: "books, not memorized"
The orchestrator treats this like a senior engineer treats reference docs — knows the catalog exists, knows roughly what's in each book, opens the specific page when needed, cites the decision, closes the book. The library can be huge because it's pulled, not preloaded.

## Self-extension
When the orchestrator discovers a new high-value tool/pattern during a project (or in fresh research), it ADDS an entry to the relevant `ecosystem/*.md` and notes the date. The library grows; it never silently goes stale. Each entry carries a `verified:` date so staleness is visible.

## Honesty about freshness
Entries marked `⚡` were verified from live sources during a research burst. Entries marked `(corpus)` come from this project's accumulated research (still recent, May 2026). Anything the orchestrator can't verify when it matters, it re-fetches rather than trusting a stale catalog line — exactly the FM-12 (stale-derived-docs) discipline applied to the library itself.

## What this enables
Because the library captures what the BEST agentic engineers actually use — Karpathy's CLAUDE.md discipline, Boris Cherny's Claude Code patterns, the agentskills.io 40-tool standard, token-compression like headroom, code-graph indexing like codegraph, memory like Letta/agentmemory, orchestration like ADK/LangGraph/OpenAI-Agents-SDK — a project generated by OS-Setup starts from the collective frontier, not from scratch. That's the "beat everyone" lever: you inherit the ecosystem's best, auto-selected for your problem.
